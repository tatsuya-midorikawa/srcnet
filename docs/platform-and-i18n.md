# 移植性と国際化

macOS と Windows を対等な第一級プラットフォームとして扱う。Linux は「解析対象としての Linux カーネル ソース」が主目標であり、**実行環境としては対応しない**（[設計判断](decisions.md) ADR-10）。動作しないことを意図するものではないが、検証していない以上「対応」とは呼ばない。

本書は [開発規約](../.github/instructions/fsharp-dotnet.instructions.md) の NFR-1（両 OS 動作）と NFR-4（CJK 動作）を、srcnet 固有の具体策へ落としたものである。

## 1. パスの扱い

### 1.1 正規化

ノード ID とグラフ内表現には、次の正規化を適用した**論理パス**を使う。

| 項目 | 規則 |
| --- | --- |
| 区切り | `/` に統一する |
| 基準 | リポジトリ ルートからの相対 |
| Unicode | NFC に正規化する |
| 大文字小文字 | 変換しない。原文のまま保持する |

一方、ファイルシステムへアクセスする際は、OS 固有の**物理パス**へ戻す。論理パスと物理パスを型で区別し、混同をコンパイル時に防ぐ。

### 1.2 Unicode 正規化が必須である理由

macOS の APFS / HFS+ はファイル名を分解形（NFD 相当）で返すことがあり、Windows の NTFS は通常合成形（NFC）で保持する。正規化しなければ、同じリポジトリを macOS と Windows でインデックスしたときに**異なるノード ID が生成され、決定性要件（NFR-11）が破れる**。

したがって NFC 正規化は移植性ではなく決定性の要件である。

### 1.3 大文字小文字

Windows と macOS の既定は大文字小文字を区別しないが、Linux カーネルや Chromium は区別するファイルシステム上で開発されている。

- 論理パスでは大文字小文字を区別する
- 大文字小文字のみが異なるパスが同一ツリーに存在し得ることを前提とする。これらを暗黙に統合しない
- 大文字小文字を区別しないファイルシステム上で衝突を検出した場合は、診断として報告し、どちらを採用したかを明示する

### 1.4 Windows 固有の制約

| 制約 | 対策 |
| --- | --- |
| `MAX_PATH`（260 文字）制限 | 長いパスに対応する設定を有効化し、必要に応じて拡張パス表記を使う。Chromium は深い階層を持ち、この対応なしでは走査が失敗する |
| 予約名（`CON`, `PRN`, `AUX`, `NUL`, `COM1`〜, `LPT1`〜） | ファイル名として現れ得る。生成物のファイル名に利用者入力を使わない |
| 末尾のドット・空白 | 物理パス生成時に丸められないよう扱う |
| ドライブ文字、UNC パス | 論理パスには含めない |
| ジャンクション、リパース ポイント | シンボリック リンクと同様に扱う（1.5） |

### 1.5 リンクと循環

- シンボリック リンクは既定で追跡しない。追跡する場合も、解決先がルート外に出るものは拒否する
- ディレクトリの循環を検出し、無限走査を防ぐ。これは NFR-5（フリーズしない）の要件でもある
- ハード リンクによる同一実体の重複は、内容ハッシュで検出して診断する

## 2. 文字エンコーディング

### 2.1 検出順序

大規模リポジトリには非 UTF-8 のファイルが実在する。Linux カーネルには歴史的経緯で複数の符号化のファイルが含まれる。

1. BOM があればそれに従う（UTF-8 / UTF-16 LE / UTF-16 BE）
2. UTF-8 として妥当ならば UTF-8 とみなす
3. 妥当でなければ、レガシー符号化の判定を試みる
4. 判定できなければ、置換文字を用いて復号し、当該ファイルに診断フラグを付ける

判定は決定的でなければならない。統計的推定を使う場合も、固定の規則と固定の閾値を用い、実行ごとに結果が揺れてはならない。

### 2.2 対応するレガシー符号化

CJK 要件（NFR-4）のため、少なくとも次を扱えるようにする。

| 言語圏 | 符号化 |
| --- | --- |
| 日本語 | Shift_JIS (CP932), EUC-JP, ISO-2022-JP |
| 簡体字中国語 | GB18030, GBK (CP936) |
| 繁体字中国語 | Big5 (CP950) |
| 韓国語 | EUC-KR (CP949) |

復号は `System.Text.Encoding.CodePages` を使わず、同梱した変換表で自前で行う（[設計判断](decisions.md) ADR-9）。表は `tools/generate_encoding_tables.py` が生成し、Deflate で圧縮した埋め込み資源として持つ。展開は、実際にその符号化のファイルへ出会ったときだけ行う。

### 2.3 判定が曖昧な場合

これらの符号化は原理的に構造だけでは区別できない。たとえば EUC-JP のバイト列は Shift_JIS としても妥当であり、後者では半角カタカナの並びとして解釈される。

判定が単一の符号化へ確定しない場合、候補の先頭を確定値として扱わない。既定では**復号せず**、候補を成果物へ残して抽出を見送る。誤った復号による文字化けを成果物へ載せるより、抽出しないほうが安全側に倒れる。

利用者は `srcnet index --assume-encoding <名>` で符号化を明示できる。指定が候補に含まれる場合だけ適用し、適用した符号化は `manifest.json` に記録する。この指定は利用者が持ち込んだ事実であり、srcnet の推測ではない。

### 2.4 グローバリゼーション設定

**`InvariantGlobalization` を有効にしてはならない。** 有効にすると文化圏依存の大文字小文字変換と照合順序が失われ、CJK を含む検索が正しく動作しない。

- 大文字小文字を無視する比較には、序数ベースのケース フォールドを使う。文化圏依存の比較を既定にしない（トルコ語の `i` 問題を避けるため）
- 表示順序の整列に文化圏依存の照合を使う場合、成果物の決定性に影響しない箇所に限定する
- Native AOT / trimming を採用する場合、必要なグローバリゼーション データが成果物に残ることを publish 結果で検証する

## 3. テキスト処理

| 項目 | 規則 |
| --- | --- |
| 内部表現 | UTF-8。走査は Unicode スカラー値単位 |
| 分割・切り詰め | 書記素クラスタ境界で行う。UTF-16 コード単位や UTF-8 バイトで切らない |
| 表示幅 | 東アジア文字幅（Wide / Fullwidth）を 2 桁として計算する。桁揃えを `String.Length` で行わない |
| 識別子 | CJK 識別子を扱えるようにする。Java、Python、C# などは CJK 識別子を許可する |
| 語分割 | `snake_case` / `camelCase` に加え、CJK は文字 n-gram で分割する（[ストレージ](storage.md) 7.2） |
| 改行 | LF / CRLF / CR を認識する。行番号は改行種別によらず一致しなければならない |

## 4. コンソール出力

- 標準出力の符号化を明示的に UTF-8 に設定する。Windows の既定コード ページのままでは CJK が文字化けする
- 端末が UTF-8 を扱えない場合に備え、`--json` 出力はエスケープで安全に表現できるようにする
- 進捗表示は端末幅と文字幅を考慮し、CJK を含むパスで表示が崩れないようにする
- 端末でない出力先（パイプ、リダイレクト）では、制御シーケンスを一切出力しない

## 5. その他の OS 差異

| 項目 | 扱い |
| --- | --- |
| 改行コードの既定 | 出力ファイルの改行はプラットフォームによらず固定する。決定性のため |
| ファイル ロック | Windows は開いているファイルの削除・改名に制約がある。生成物の差し替えは、この制約下でも原子的に動作する手順にする |
| 時刻精度 | ファイル更新時刻の精度と粒度が OS で異なる。変更検出の高速パスはこれを前提にし、最終判断は内容ハッシュで行う |
| 大文字小文字を無視する環境変数 | Windows のみ。環境変数名の比較を OS 依存にしない |
| パス長・ファイル数の上限 | 走査は上限に達しても失敗せず、診断として報告する |

## 6. 検証

上記は主張ではなく検証項目である。対応するテストは [テスト](testing.md) に定義する。特に次は必須とする。

1. CJK を含むファイル名・ディレクトリ名・識別子・内容を含むコーパスで、インデックスと検索が正しく動作する
2. macOS でインデックスした成果物と Windows でインデックスした成果物が、バイト単位で一致する
3. レガシー符号化のファイルを含むコーパスで、文字化けと欠落が起きない
4. 長いパス、予約名、リンク循環を含むツリーでクラッシュしない
