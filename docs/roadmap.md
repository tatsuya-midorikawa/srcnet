# ロードマップ

各マイルストーンは、[要件](requirements.md) 6 の受け入れ基準を満たしたときに完了とする。特に「macOS と Windows の両方で検証済み」と「性能回帰なし」は全マイルストーン共通の完了条件である。

## M0 — 基盤

- ソリューションとプロジェクト構成の作成（`Core` / `Text` / `Cli` と対応するテスト）
- CI の構築（macOS + Windows マトリクス、ビルド・テスト・フォーマット・静的解析）
- ベンチマーク プロジェクトの雛形と、小規模コーパスの取り込み
- `.editorconfig` の改行・BOM 方針の確定（[設計判断](decisions.md) の未決事項）

**完了条件:** 両 OS の CI が緑。空の CLI が両 OS で起動する。

## M1 — 構造グラフ

- ファイル走査、無視設定、リンクと循環の処理
- 言語判定、エンコーディング検出、内容ハッシュ
- `Repository` / `Directory` / `File` ノードと `CONTAINS` エッジ
- 論理パス正規化（NFC、区切り統一）と ID 計算

**完了条件:** `linux` コーパスの走査が完了し、両 OS で成果物がバイト一致する。

## M2 — C / C++ 抽出

- T1 行指向抽出（include、定義候補、根拠コメント）
- T2 構文抽出（型、関数、フィールド、マクロ）
- 構文解析器の選定を実測で確定（[設計判断](decisions.md) ADR-3）
- `#ifdef` 追跡と `GUARDED_BY`

**完了条件:** `linux` コーパスでシンボル抽出が完了し、ゴールデン テストが通る。

## M3 — 解決

- 大域シンボル表の外部ソート構築
- include 解決、呼び出し・参照・継承の解決
- 確度（`EXTRACTED` / `RESOLVED` / `AMBIGUOUS`）の付与

**完了条件:** 解決率と確度分布を計測し、`AMBIGUOUS` の内訳を説明できる。

## M4 — ストレージと照会

- セグメント形式、CSR、文字列 blob、ID マップ
- 名前索引と n-gram 索引（CJK 対応）
- `search` / `show` / `neighbors` / `path` / `stats` / `verify`
- トークン予算と JSON 出力

**完了条件:** 照会レイテンシが [性能](performance.md) の目標内。CJK 検索テストが通る。

## M5 — 増分更新

- 変更検出、tombstone、デルタ セグメント、コンパクション
- 改名・移動の検出
- 影響範囲に限定した再解決

**完了条件:** 増分等価性テスト（T-2）が通り、増分更新の目標時間を満たす。

## M6 — 解析と補強

- 中心性、コミュニティ検出、決定的なコミュニティ命名
- ビルド記述、`Kconfig`、`OWNERS` / `MAINTAINERS`、git 共変更
- `explain` / `impact` / `context`

**完了条件:** コミュニティ分割が決定的に再現し、ハブ検出が機能する。

## M7 — 規模検証

- `chromium` コーパスでの完全インデックス
- メモリ上限、所要時間、生成物サイズの実測
- [性能](performance.md) の目標値を実測値で置き換える

**完了条件:** `chromium` のインデックス生成と照会が目標内で完了する。達成できない場合は原因を特定し、目標または設計を改訂する。

## M8 — 多言語対応の拡大

- Rust、Python、JavaScript / TypeScript
- 続いて Java、Go、C#、F#、Objective-C / Objective-C++

**完了条件:** 各言語のゴールデン テストが通り、既存言語の性能に回帰がない。

## M9 — 公開準備

- MCP アダプター（標準入出力のみ）
- `SECURITY.md`、`CONTRIBUTING.md`、配布形態の確定
- 利用者向けドキュメントの整備

## 未決事項

[設計判断](decisions.md) の未決事項に加え、次を解決する必要がある。

| 項目 | 決着させる時期 |
| --- | --- |
| 構文解析器の選定（自作 / 既存文法） | M2 |
| Linux を対応実行環境に含めるか | M0 |
| 改行コードと BOM の方針 | M0 |
| 生成物の配布形態（Native AOT / 単一ファイル / フレームワーク依存） | M7 |
| 複数リポジトリ統合の生成物単位 | M6 |
| コミュニティ命名の品質が実用に足るか。足りない場合の代替（LLM は使わない前提での改善） | M6 |
| 全文検索を将来的に別コンポーネントとして持つか | M9 以降 |
| 大規模コーパスを CI で回すための実行基盤（ホスト型ランナーの制限に収まるか） | M7 |
