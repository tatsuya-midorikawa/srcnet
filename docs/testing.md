# テスト

## 1. 方針

[要件](requirements.md) の非機能要件は、主張ではなく検証項目である。本書は各要件をどのテストで担保するかを対応付ける。

純粋な領域ロジックは高速で決定的な単体テストで、I/O 境界は統合テストで検証する。純粋関数をモックしない。

## 2. 種別

| 種別 | 対象 |
| --- | --- |
| 単体 | ID 計算、正規化、字句走査、ランキング、CSR 操作、予算計算、構文木ラッパーの境界検証 |
| Property | 直列化の往復、正規化の冪等性、CSR と隣接集合の対応、予算単調性 |
| Fuzz | 抽出器、エンコーディング検出、セグメント読み込み、構文解析の相互運用境界 |
| ゴールデン | 小さな固定コーパスに対する抽出結果 |
| 統合 | インデックス生成から照会までの通し |
| 移植性 | macOS / Windows での結果一致 |
| 性能 | [性能](performance.md) の目標値 |
| Stress / 長時間 | 資源枯渇、並行、中断、長時間実行 |

## 3. 必須テスト

以下は「これが通らなければ設計要件を満たしていない」ことを意味するテストである。

### T-1 決定性

1. 同一コーパスを 2 回インデックスし、`manifest.json` を含む全ファイルがバイト単位で一致する
2. `--jobs 1` と `--jobs 16` の生成物が一致する
3. macOS で生成した成果物と Windows で生成した成果物が一致する

3 は NFR-11 の中核であり、パス正規化・Unicode 正規化・改行の扱いを同時に検証する。

### T-2 増分等価性

1. 完全生成 → ファイル変更 → 増分更新、の結果が
2. 変更後の状態からの完全生成、と論理的に等価である

追加・変更・削除・改名・移動、および複数ファイルの同時変更について検証する。コンパクション後も等価性が保たれることを併せて確認する。

### T-3 AI 不使用と非通信

1. 製品プロジェクトの依存閉包に、ネットワーク クライアントとモデル ランタイムが含まれないことを検査する
2. インデックス生成と照会の全経路で、ネットワーク接続が発生しないことを検証する
3. 生成物にモデル由来の生成テキストが含まれないこと（要約フィールドが存在しないこと）を検査する
4. 唯一のネイティブ依存である tree-sitter は、構築時にのみ取得し、実行時に通信しないことを確認する。取得は版と SHA-256 の固定に基づく（[設計判断](decisions.md) ADR-3）

### T-4 CJK

| 検証項目 |
| --- |
| CJK を含むファイル名・ディレクトリ名で走査・索引・検索・出力が正しい |
| CJK 識別子の抽出・解決・検索が正しい |
| Shift_JIS / EUC-JP / ISO-2022-JP / GB18030 / Big5 / EUC-KR のファイルで文字化けと欠落がない |
| CJK を含む出力の端末表示が、東アジア文字幅を考慮して崩れない |
| 書記素クラスタ境界での切り詰めが正しい（結合文字、絵文字、異体字セレクタを含む） |
| NFC / NFD の差異が ID に影響しない |

### T-5 クラッシュ・フリーズ耐性

| 入力 / 状況 | 期待 |
| --- | --- |
| 巨大な単一ファイル（4 GiB 超を含む） | 診断付きで継続、またはスキップ。クラッシュしない |
| 深いディレクトリ階層、長いパス | 上限に達しても診断して継続 |
| シンボリック リンクの循環 | 検出して終了。無限走査しない |
| 極端に長い 1 行、深い入れ子構文 | 上限で打ち切り、指数的劣化なし |
| 壊れた符号化、不正なバイト列 | 置換して継続 |
| 読み取り権限のないファイル | 診断して継続 |
| FIFO・ソケット・デバイス（`.gitignore` を含む） | 開かずに結果を決める。無期限に blocking しない |
| 巨大・長行の無視ファイル | 上限で打ち切り、診断して継続 |
| 処理中の中断（取り消し） | 大きなセグメントの書き出し中でも定めた時間内に終了コード 5 で停止し、公開済みの成果物を変更しない |
| 照会と生成の同時実行 | 照会は一貫した結果を返す。欠損も世代混在も起きない |
| 公開途中での強制終了 | 再起動後に旧世代か新世代のどちらか一方を完全に読める |
| 長時間の連続実行 | メモリ・ハンドルのリークがない |

### T-6 セキュリティ

| 検証項目 |
| --- |
| ルート外を指すシンボリック リンクで脱出できない |
| 無視ファイルのパターンでルート外を参照できない |
| リンクである無視ファイルを開かず、その規則を適用しない |
| リンク（symlink / junction / reparse point）である出力先へ書き込まず、リンク先を変更しない |
| 対象リポジトリ由来のコードが実行されない |
| ファイル名・識別子に含まれる ANSI エスケープが端末出力で無害化される |
| 破損した生成物、非互換な形式版が明示的に拒否される |
| 改変されたセグメント名（絶対パス、`../`、UNC、区切りの混在、代替データ ストリーム）で成果物外を読めない |
| 型・範囲・不変条件が不正な生成物が、内部エラーではなくドメイン エラーになる |
| ネイティブ相互運用と mmap 境界の fuzz テストで異常終了しない |

ANSI エスケープの検証は、リポジトリから端末表示を偽装できないことを確認するもので、実際に起こり得る攻撃である。

### T-7 規模

| 検証項目 |
| --- |
| `linux` コーパス全体のインデックス生成が完了する |
| `chromium` コーパス全体のインデックス生成が完了する |
| いずれもピーク RSS が上限内に収まる |
| 生成物に対する照会が目標レイテンシ内で完了する |

## 4. CI マトリクス

| ジョブ | OS | 実行契機 | 内容 |
| --- | --- | --- | --- |
| build-test | macOS, Windows | 全 PR | Release ビルド、全テスト、フォーマット、静的解析 |
| parser | macOS, Windows | 全 PR | 固定した取得元の検証、tree-sitter の構築、解析器ありでのテスト |
| determinism | macOS, Windows | 全 PR | T-1、両 OS 成果物の突き合わせ |
| corpus-small | macOS, Windows | 全 PR | `micro` / `medium` / `cjk` / `pathological` |
| bench-small | macOS, Windows | 全 PR | 小規模ベンチマークと回帰検出 |
| corpus-large | macOS, Windows | 定期 | `linux` / `chromium` |
| soak | macOS, Windows | 定期 | 長時間実行、リーク検出 |
| deps-audit | いずれか | 全 PR + 定期 | 依存の脆弱性検査、依存閉包の検査（T-3） |

macOS と Windows の両方が必須である。一方でも未検証または失敗なら完了扱いにしない。

Linux は対応実行環境に含めない（[設計判断](decisions.md) ADR-10）。Linux ランナーは、大規模コーパスの取得と補助的な検証のために利用してよいが、合否判定には使わない。取得したコーパスに対する索引と検証は macOS / Windows のランナーで行う。

## 5. コーパスの管理

- 外部リポジトリはコミット SHA で固定する。追従は明示的な更新として行う
- 大規模コーパスは CI でキャッシュし、毎回の取得を避ける
- CJK と病的入力のコーパスは、本リポジトリ内に小規模な合成データとして保持する。外部依存にしない

### 5.1 リポジトリ内の固定コーパス

| ディレクトリ | 内容 |
| --- | --- |
| `tests/corpus/micro` | 宣言と定義、名前空間、テンプレート、継承、マクロ、`#ifdef`、ビルド記述を最小限ずつ含む C / C++ と `Makefile` / `Kconfig`。生成コード・ベンダー コード・テストの各フラグの検体を含む |
| `tests/corpus/cjk` | CJK 識別子・コメント・ファイル名を含むファイル。UTF-8、UTF-16LE / BE、および復号方針の検体としてのレガシー符号化 |
| `tests/corpus/pathological` | 極端に長い 1 行、深い入れ子、巨大ファイル、壊れた符号化、NUL 混在、途中で切れた UTF-8、閉じない文字列とコメント、構文誤り |

## 6. ゴールデン テスト

抽出規則の回帰を検出する唯一の手段である。期待値は `tests/golden/<コーパス>.<段階>.txt` に、
決定的なテキスト表現で保存する。バイナリ成果物を期待値にしない。

- 期待値には行範囲を含め、バイト位置は含めない。位置を含めると、コーパスの些細な編集で全件が差分になる
- 期待値は LF・BOM なし UTF-8 で保存する（[設計判断](decisions.md) ADR-7）
- 手作業で書き換えない。次のコマンドで再生成する

```sh
SRCNET_UPDATE_GOLDEN=1 dotnet test tests/Srcnet.Tests --filter Golden
```

構文解析器が無い環境では T1 の期待値だけを検証する。省略したことはテスト出力へ
`SKIPPED` として記録し、`SRCNET_REQUIRE_PARSER=1` を設定した環境（CI の `parser` ジョブ）では
省略そのものを失敗にする。「解析器が無いから通った」状態を成功として扱わないためである。

## 7. テストの原則

- 公開された振る舞いを検証し、内部実装手順に固定しない
- 時刻・乱数・実行順・ネットワークに暗黙依存しない。固定の待機時間で非同期完了を待たない
- 1 つのテストが失敗したときに原因を特定できる粒度にする
- 不具合修正には、修正前に失敗する最小の回帰テストを先に追加する
- テストと benchmark の依存は開発専用として隔離し、製品成果物に含めない
