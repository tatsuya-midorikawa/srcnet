# AI skills

This directory contains distributable agent skills. Each package has a
`SKILL.md` with discovery metadata and instructions.

| Skill | Purpose |
| --- | --- |
| [srcnet](srcnet/SKILL.md) | Reuse a srcnet index through bounded JSON queries, then confirm relevant source |
| [srcnet-index](srcnet-index/SKILL.md) | Generate manifest and segments, verify integrity, and record the three context paths |

## Make the skill available to an agent

`ai/skills/` is the authoring location, not a default Copilot skill-discovery
directory. Copy each desired skill directory to the corresponding location.
Use `srcnet` and/or `srcnet-index` for `<skill-name>`:

| Scope | Copilot location |
| --- | --- |
| One target repository | `<target-repository>/.github/skills/<skill-name>/SKILL.md` |
| Personal, across repositories | `~/.copilot/skills/<skill-name>/SKILL.md` |

Other clients have their own skill-discovery locations. Review an existing
destination before replacing it. This repository does not automatically install
the skill, change global configuration, or create an index.

## Provide the working context

For generation, provide the trusted executable, source root and output directory.
The `srcnet-index` skill records their resolved absolute paths as the top-level
`SRCNET`, `SOURCE_ROOT` and `INDEX_DIR` string fields in `manifest.json`.
For subsequent queries, give the `srcnet` skill that manifest's path; it reads
and validates the three fields. Explicit trusted user settings take precedence.
Older/CLI-only manifests without them still use supplied context or defaults.

An index outside the source tree is supported through explicit `--out`;
the default is `<source-root>/_srcnet`. The CLI does not automatically consume
the added fields, and they do not authorize executing an untrusted binary.
The agent needs access to the selected paths. Store real machine-specific paths
only in local generated manifests, not in the distributed skill or its example.

The graph metadata in `manifest.json` is generated by `srcnet index`, not filled
in by hand. The generation skill adds only the three context fields afterwards.
The [sample manifest](srcnet/manifest.example.json) combines real small-index
metadata with illustrative context paths. The skill explains each field.
The sample alone is not usable without matching segments, and must not replace
an existing manifest.

To generate an index, explicitly ask the agent to use `srcnet-index` and provide
the source and output directories. This skill deliberately defaults to T1 with
two workers unless another tier/parallelism is requested; the CLI itself defaults
to T2. It generates manifest and segments, checks integrity, records and validates
the three paths, and returns the manifest location. Existing output and resource limits are checked
before generation.

For example, ask the agent to use the existing srcnet index to find relevant
files for a feature, inspect their neighborhoods, and read only the source needed
to explain the result. The `srcnet` skill defaults to read-only investigation and does
not rebuild the index automatically.

For continued use, choose a stable index location rather than session storage.
After moving an index, retain its segments and update stale context paths with
authorization. Direct CLI generation does not add the fields; use `srcnet-index`
for that step. Current CLI version 0.1.0 accepts enriched manifests for queries
and ordinary `verify`, but `verify --deterministic` reports a manifest mismatch
because it rebuilds without those additions. This is documented in both skills.
The skills do not eliminate extraction limitations; they check diagnostics,
truncation, freshness and original-source evidence.
