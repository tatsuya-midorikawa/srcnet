# [P1] 索引と現在のソースが一致しているか確認できるようにする

- 状態: 未着手
- 種別: 機能 / 結果の信頼性
- 起票日: 2026-09-27
- 依存: なし。増分更新を待たず、読み取り専用の確認から対応する。

## 確認した事実

- [照会スキル](../ai/skills/srcnet/SKILL.md) は、索引がスナップショットであり、鮮度不明の場合に元ソースを確認するよう求めている。
- [QueryCommands.fs](../src/Srcnet.Cli/QueryCommands.fs) の `withView` は指定索引を開いて照会する。現在の元ソースとの照合は行わない。
- [Commands.fs](../src/Srcnet.Cli/Commands.fs) の通常の `verify` は成果物の整合性を検査する。`--deterministic` は再生成を伴う重い検証で、軽量な鮮度確認とは異なる。
- [ストレージ](../docs/storage.md) のファイル表には内容ハッシュがある。サイズ・更新時刻だけで同一性を確定しない方針も記載されている。

## 利用者の困りごと

ソース編集やブランチ切替の後も、古い名前・行範囲を正常な照会結果として受け取る。`verify` が成功したことだけで最新の索引だと思い込む可能性がある。

## 改善内容

- 利用者が指定したソースと、索引内のファイル内容ハッシュを照合する読み取り専用の操作を用意する。
- まず照会対象の少数ファイルを確認できる形にし、全ソースの照合とは明確に区別する。未確認を「変更なし」と表示しない。
- 変更あり、削除済み、読取不可、未確認を区別し、対応する再索引手順を案内する。自動再生成はしない。
- 照会結果と索引世代の対応を識別できるようにし、異なる索引の NodeId を混用しにくくする。
- 通常照会のたびに全リポジトリをハッシュせず、明示的な確認時だけ必要な I/O を行う。

## 対象外

自動監視、ブランチ切替フック、増分更新、未確認ファイルも含めた鮮度の保証。

## 受け入れ条件

- [ ] 同サイズの書き換え、時刻を戻した変更、削除、読取拒否を区別できる。
- [ ] 確認したファイル集合と未確認の範囲を JSON / テキストで明示する。
- [ ] 改名・別ルート・CJK パス・ルート外へのリンクを macOS / Windows で検証する。
- [ ] 確認のファイル数・読取バイト数・時間を制限し、キャンセルできる。
- [ ] 通常の search / show の起動・照会性能を悪化させず、索引を変更しない。
- [ ] [QueryCliTests.fs](../tests/Srcnet.Tests/QueryCliTests.fs) 等で検証し、整合性と鮮度の違いを資料へ反映する。
