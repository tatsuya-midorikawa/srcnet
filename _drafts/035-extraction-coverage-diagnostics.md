## 確認した事実

- [Program.fs](../src/Srcnet.Cli/Program.fs) の `--version` は構築済みの文法を列挙する。今回の環境でも C / C++ 以外の文法が表示された。
- [抽出](../docs/extraction.md) 3.2 は、文法の存在と T2 グラフ抽出の対応が別であり、現行の T2 抽出は C / C++ と説明している。
- [Commands.fs](../src/Srcnet.Cli/Commands.fs) の `reportIndex` は要求段階、到達段階、解析器の有無、全体の `extractedFiles` を返す。
- 同ファイルの `statsWithCancellation` は言語・符号化・参照候補を集計するが、言語ごとの T2 / T1 / 抽出なしとその理由をまとめて再確認する形ではない。
- 小規模コーパスの実行でも `complete: true` と終了コード 4 が同時に返った。完全な走査と診断なしの抽出成功は同義ではない。

## 利用者の困りごと

「文法はあるのにシンボルが少ない」「T2 を指定したのに何が T1 になったか分からない」という状況の説明を、複数の出力と仕様から組み立てる必要がある。

## 改善内容

- 構築済み文法、実装済みの抽出段階、要求段階、実際の到達段階を区別して表示する。
- 言語ごとのファイル数と T2 / T1 / 抽出なしの件数、文法不在・未対応・符号化・サイズ・時間制限等の理由を集計する。
- 生成後も `stats` 等から同じ集計を参照できるようにし、件数と上限付きの代表例を分ける。
- 理由ごとに、現行で可能な対応を示す。未実装の機能や、異なる文法を入れるだけでは解決しない状況を正しく案内する。
- README または入門資料から、言語と段階を選ぶ小さな対応表へ誘導する。

## 対象外

新しい言語の T2 抽出実装、全ファイルの無制限な診断一覧、解析品質の完全保証。

## 受け入れ条件

- [ ] 混在言語、解析器なし、一部文法のみ、T0 / T1 / T2 指定で集計を検証する。

- [ ] サイズ超過、符号化不明、抽出時間制限を理由別に再確認できる。
- [x] 診断例が打ち切られても合計と省略の有無を把握でき、出力量は有界である。
- [ ] 保存形式の互換性と決定性を維持し、macOS / Windows のテストと資料更新を終える。
