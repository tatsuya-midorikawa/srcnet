# [P2] search をノード種別とパス範囲で絞り込めるようにする

- 状態: 未着手
- 種別: 機能 / 検索の使いやすさ
- 起票日: 2026-09-27
- 依存: なし。n-gram 索引や参照解決とは独立して対応できる。

## 確認した事実

- [Args.fs](../src/Srcnet.Cli/Args.fs) の `SearchArguments` は文字列、大小文字の扱い、出力制限を持つが、ノード種別・パス範囲の指定を持たない。
- [Query.fs](../src/Srcnet.Storage/Query.fs) の `searchCore` は名前・修飾名・パスの一致を収集し、[QueryCommands.fs](../src/Srcnet.Cli/QueryCommands.fs) の `search` が順位付けと返却上限を適用する。
- [照会スキル](../ai/skills/srcnet/SKILL.md) は、同名のディレクトリとシンボルを区別し、検索結果から目的の種別を選ぶよう求めている。

## 利用者の困りごと

「File だけ」「特定サブディレクトリ内の Function だけ」を調べたい場合も、混在する結果から後処理で選別する必要がある。返却上限の後で除外すると、欲しい候補が落ちたまま空になる。

## 改善内容

- `search` にノード種別と論理パスの範囲指定を追加する。オプション名と AND / OR の意味を明示する。
- フィルターを順位付け・返却上限より前に適用し、後処理での取りこぼしを避ける。
- パスは区切りの境界で判定し、NFC、大小文字、macOS / Windows の入力表記を仕様化する。
- 既存の候補数・バイト数の安全上限を維持し、絞り込みにより未調査となった範囲を完全な該当なしと扱わない。
- JSON の照会条件にフィルターを記録し、CLI ヘルプとスキルに使い方を追加する。

## 対象外

自然言語検索、全文検索、無制限の結果取得、独自の複雑なクエリ言語。

## 受け入れ条件

- [ ] 同名の File / Directory / Function が混在しても目的の種別を選べる。
- [ ] パスの共通接頭辞だけが一致する隣のディレクトリを誤って含めない。
- [ ] 少ない `--limit` でも範囲内の上位候補を返し、件数と省略表示が整合する。
- [ ] 無効な種別、不正パス、CJK、空結果、上限到達を [QueryTests.fs](../tests/Srcnet.Tests/QueryTests.fs) と [QueryCliTests.fs](../tests/Srcnet.Tests/QueryCliTests.fs) で検証する。
- [ ] フィルター未指定時の既存結果・順位・決定性を維持し、両 OS で性能を比較する。
