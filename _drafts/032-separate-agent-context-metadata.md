# [P1] エージェントの機械固有設定を決定的な manifest から分離する

- 状態: 未着手
- 種別: 機能 / エージェント連携 / 決定性
- 起票日: 2026-09-27
- 依存: なし。既存スキルとの移行互換性を保つ。

## 確認した事実

- [AI skills](../ai/skills/README.md) と [照会スキル](../ai/skills/srcnet/SKILL.md) は、生成後の manifest に `SRCNET`、`SOURCE_ROOT`、`INDEX_DIR` を追記する方式を定めている。
- 同文書は、追記済み manifest に `verify --deterministic` を実行すると、再生成側に追記がないため差分になると明記している。
- [Commands.fs](../src/Srcnet.Cli/Commands.fs) の `checkDeterminism` は生成条件から再構築し、`compareArtifacts` で manifest も比較する。
- CLI はこの 3 項目を設定として自動使用しない。移動後のパス検証や信頼できる実行ファイルの選択はスキル側の責任である。

## 利用者の困りごと

推奨スキルで生成した索引が決定性検証に通らず、正常なグラフとメタデータ差分を見分ける必要がある。端末固有の絶対パスは共有・移動にも適さない。

## 改善内容

- 決定的なグラフ情報と、ローカル実行環境の設定を分離する。小さな別ファイルを第一候補とし、不要な設定基盤は導入しない。
- manifest の場所だけを渡せる既存の利用導線を保ちつつ、スキルがローカル設定を安全に検出・検証できるようにする。
- 旧方式の追加フィールドを読む互換処理と、利用者が明示的に許可したときだけ行う移行手順を用意する。
- 索引の明示指定、信頼済みの実行ファイル、ユーザーによる設定の優先順位を維持する。索引由来のパスだけでプログラムを実行しない。
- スキル、サンプル manifest、利用ガイドを同時に更新する。

## 対象外

manifest の比較を丸ごと省略する対応、セグメント整合性検証の弱体化、通常照会時の自動書き換え。

## 受け入れ条件

- [ ] 同じ入力・生成条件で、スキル利用後も CLI 生成物の決定性検証が成功する。
- [ ] 異なる機械の実行ファイル・ソース配置を指定しても、グラフ本体のバイト列は変化しない。
- [ ] 新旧形式、移動済み索引、欠損設定、不正な JSON、不信頼の実行ファイルを検証する。
- [ ] 通常の検索は読み取り専用で、manifest の構造検証・チェックサム検証は従来どおり機能する。
- [ ] macOS / Windows の空白・CJK を含むパスで生成、照会、移行を検証する。
