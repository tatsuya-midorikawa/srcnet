# [P2] ファイルが走査対象から外れる理由を確認できるようにする

- 状態: 未着手
- 種別: 使いやすさ / 索引対象の診断
- 起票日: 2026-09-27
- 依存: JSON 出力は 033 の契約と揃える。035 の抽出段階の診断とは役割を分ける。

## 確認した事実

- [Walk.fs](../src/Srcnet.Discovery/Walk.fs) の `processEntry` は、組み込みの除外と無視規則を評価し、`ignored` の場合は診断を追加せず処理を省く。
- 同じ処理で、リンクのスキップ・ルート外参照・深さ超過には既存の診断がある。「すべての除外理由が診断されない」わけではない。
- [クエリと CLI](../docs/query-and-cli.md) は、ドットディレクトリの除外を `--no-gitignore` や否定規則では解除できないと説明している。
- [Args.fs](../src/Srcnet.Cli/Args.fs) の公開コマンドには、指定パスの採否や適用された除外規則を照会する操作がない。

## 利用者の困りごと

検索結果にファイルが現れないとき、未対応の抽出、無視設定、組み込みの除外、古い索引のどれが原因か切り分けにくい。設定を変えて重い再索引を繰り返すことになる。

## 改善内容

- 明示的に指定したパスについて、走査対象か、どの親ディレクトリ・無視規則・組み込み制約で除外されるかを表示する。
- 既存の採否判定を共有し、診断専用の別実装で `.gitignore` / `.srcnetignore` の意味を変えない。
- 無視規則による除外では、適用された規則と定義元を確認できるようにする。
- 元ソースの本文を読み込んだり抽出したりせず、索引を生成・変更しない軽量な操作にする。
- 未列挙・読取不可・存在しない・設定で除外を区別し、判定できないものを採用・除外と断定しない。
- 複数パスの確認にも件数・出力予算とキャンセルを設ける。既存の除外既定値は変えない。

## 対象外

隠しディレクトリの一律採用、秘匿ファイルの本文表示、無視設定の自動編集、抽出品質や索引鮮度の診断の再実装。
