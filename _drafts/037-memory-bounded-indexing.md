# [P1] 指定したメモリ予算を守って大きな索引を生成する

- 状態: 対応中
- 種別: 機能 / 大規模利用 / 安定性
- 起票日: 2026-09-27
- 依存: 既存 backlog 026 の再現可能な測定条件と連携する。測定作業そのものは重複起票しない。

## 確認した事実

- [ロードマップ](../docs/roadmap.md) は spill・外部ソート・セグメント分割・メモリ上限を、M3 / M5 より先に実装する優先作業としている。
- [Walk.fs](../src/Srcnet.Discovery/Walk.fs) は収集したディレクトリ・ファイルを配列化して返し、[Commands.fs](../src/Srcnet.Cli/Commands.fs) が走査完了後に公開用データを生成する。
- [ストレージ](../docs/storage.md) とロードマップには、部分一致の作業上限などの既存制限と、Reader の単一ビュー上限・生成全体の未達事項が区別されている。
- [既存の実測チケット](../backlogs/026-measure-linux-corpus-extraction.md) にはピーク RSS 7.95 GiB という参考記録があるが、入力 SHA の訂正後の再測定と Windows 検証は未了である。
- `--jobs` や単一ファイル上限は指定できるが、全体の `--memory-limit` は未実装である。今回、大規模コーパスの再測定は実施していない。

## 利用者の困りごと

対象規模を増やしたときの必要メモリを制御できず、並列度を下げるだけでは端末や CI のメモリ不足を防げない。

## 改善内容

- 既存ロードマップに従い、生成全体のメモリ予算と、一時ディスク使用量・上限到達時の動作を定義する。
- 抽出結果を小さな単位で退避し、外部ソートと段階的な書き出しで入力全体の常駐を避ける。
- Reader の上限と合わせてセグメントを分割し、上限超過の成果物を生成してから読めない状態にしない。
- 許容できない予算、ディスク不足、中断では明示的に失敗し、既存の公開済み索引を保持する。
- 並列度や spill の分割境界を変えても生成物の決定性を維持する。

## 対象外

このチケットだけでの Chromium 規模の受け入れ完了宣言、参照解決・増分更新の同時実装、測定せずに「高速化」とすること。

## 着手時の測定条件

- 比較基準: 進捗・退避処理の変更前に保存した Release publish (`artifacts/p1-baseline`)。元のコードは `2522bb3` を基にした作業ツリー。
- 代表入力: 既存 micro / CJK コーパスと、固定内容から生成する小ファイル・参照候補主体の合成入力。上限入力: backlog 026 と同じ固定 SHA の Linux v6.6。Linux の取得・実測は同チケットと共有し、代替の合成入力で受け入れ完了とはしない。
- 全プロセスのピーク RSS 目標: 4 GiB。時間は代表入力で基準からの非劣化、Linux は 5 分以内。一時ディスクは明示上限付きとし、上限到達は公開せず失敗する。
- 経過時間、CPU、割当量、GC、ピーク RSS、一時ディスク、成果物サイズを記録する。warm はウォームアップ後の反復、cold は OS のキャッシュ消去を実施できた場合だけ cold と表記する。
- macOS と Windows は別の実測を必要とする。片方の実行結果、cross-publish、CI の設定だけで両 OS の条件を達成したとはしない。

## 実装と検証（2026-09-27）

- 抽出入力を上限付き保持から binary 退避へ切り替え、パス・offset の外部ソートで Writer に供給する。従来の配列 API は維持した。
- lookup の大きな入力は上限付き外部マージを使い、小さい入力は元のメモリ内経路を再利用する。最大 32 run の同時マージ。
- `--memory-limit` / `--temp-limit`、managed heap 制限、協調的 RSS 監視、予算超過時の公開拒否を実装した。
- 128 MiB の物理分割、断片のチェックサム・登録・欠番検査、1 MiB の境界読取を追加した。論理長の Int32 上限は残り、超過は公開前に拒否する。
- 外部ソートの複数段マージ、退避境界の差、従来 Writer とのバイト一致、分割後の verify/stats/search/show、断片破損、予算不足、SIGINT、旧世代保持を検証した。
- [合成入力の測定](../docs/performance.md) は 1,000 / 5,000 ファイルで内容一致・4 GiB 内。時間は約 9.6% / 77.6% 悪化し、非劣化条件は未達。
- 未実装: 全体の有界化に必要な大域文字列表・ID・CSR と走査キュー・単一ディレクトリ列挙の有界化。RSS 監視は OS ハード制限ではなく、急増を厳密に防ぐ保証はない。
- 未検証: 固定 SHA の Linux、Windows、cold cache、実ディスク満杯、長時間 stress、全資源指標。割当量等の予算遵守も受け入れ未完了。基礎実装をもってチケットを完了にしない。完了日なし。
