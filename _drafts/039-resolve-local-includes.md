# [P2] C / C++ の引用形式 include をファイル間の関係として利用可能にする

- 状態: 未着手
- 種別: 機能 / 依存関係の探索 / M3 の初期範囲
- 起票日: 2026-09-27
- 依存: 037 のメモリ有界化を前提とする。既存の参照候補の保存・抽出を再利用する。

## 確認した事実

- [抽出](../docs/extraction.md) 4.3 と 5 は、include 等を未解決候補として保存する一方、ファイル間エッジには解決していないと明記している。
- [ロードマップ](../docs/roadmap.md) M3 は参照解決を計画しているが、機能は未実装である。
- 現行の `neighbors` / `path` / HTML は保存されたエッジを利用するため、候補があるだけでは include の依存関係を辿れない。

## 利用者の困りごと

C / C++ の索引を作っても、「このヘッダーを直接使うファイル」をグラフで調べられない。包含関係を依存関係と取り違えないためにも、最初の解決対象を明確にする必要がある。

## 改善内容

- M3 全体を一度に実装せず、まず `#include "x.h"` を同一ディレクトリ基準で一意に解決する範囲を実装する。
- ルート内の相対パスだけを安全に扱い、外部ファイルやビルド構成を推測して読み込まない。
- 一意に決まった関係だけを確度・根拠付きで保存し、欠損・曖昧・対応範囲外は候補のまま区別する。
- 前方・後方の探索へつなぎ、CLI と HTML から直接の include 元・先を確認できるようにする。
- 対応する条件分岐情報を失わず、構成が違うと存在しない依存を無条件の事実として提示しない。
- 解決率と未解決理由を記録し、対応範囲を抽出資料とロードマップへ反映する。

## 対象外

コンパイラやビルドの実行、T3、システムヘッダーの自動探索、呼び出し・継承解決、M3 全体の完了宣言。

## 受け入れ条件

- [ ] 同一ディレクトリ、ルート内相対パス、欠損、同名ヘッダー、条件付き include を固定入力で検証する。
- [ ] ルート外参照、リンク、CJK と大文字小文字の差を両 OS で安全に扱う。
- [ ] 解決済み・未解決・曖昧の件数が整合し、根拠と確度を照会できる。
- [ ] 前方・後方の近傍取得と HTML 表示が同じ関係を示す。
- [ ] 決定性、メモリ上限、既存抽出結果を維持し、追加処理の時間・RSS を測定する。
