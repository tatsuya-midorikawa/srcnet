# [P2] レガシー符号化の曖昧性を discovery 以降も保持する

- 種別: 文字コード判定 / 契約不一致
- 対象: `src/Srcnet.Discovery/Content.fs:34-40,140-178`, `src/Srcnet.Discovery/Walk.fs:330-342`
- 信頼度: 100%

## 問題

`Encodings.detect` は複数のレガシー符号化候補へ適合した場合に `Ambiguous = true` を返す。しかし `ContentSummary` はこの値を保持せず、`Walk` も `Undetermined` だけを診断する。

結果として、検出器が持っていた不確実性が失われ、優先順で最初の符号化を確定値としてマニフェストへ保存する。

## 確認結果

複数の対応符号化で構造的に妥当なバイト列 `81 81` を持つテキストファイルを索引した。

- 終了コードは `0`
- 診断は 0 件
- `stats` は `Shift_JIS` と確定表示した

## 影響

将来の抽出処理が任意に選ばれた符号化で復号し、CJK テキストを誤変換する可能性がある。曖昧さを隠さないという ADR-5 の契約にも反する。

## 対応案

- `ContentSummary` と `DiscoveredFile` に曖昧性を保持する
- ノードフラグまたは専用フィールドとしてストレージへ保存する
- `AmbiguousEncoding` 診断を追加し、候補情報を利用者へ提示する
- 抽出時は利用者指定、追加ヒューリスティック、または安全な未確定扱いを選べるようにする

## 完了条件

- 検出器の `Ambiguous` が discovery、writer、reader まで失われない
- 曖昧な入力で診断が発生し、単一符号化を無条件に確定表示しない
- 明確な Shift_JIS、EUC-JP、GB18030 などの既存判定は維持する
