# [P0] T1 行指向抽出を実装する

- 種別: 実装 / M2
- 対象: `src/Srcnet.Extraction/`（新規）, `src/Srcnet.Text/Words.fs`
- 依存: 014
- 参照: [抽出](../../docs/extraction.md) 2, 6, [グラフ モデル](../../docs/graph-model.md) 1, 2

## 背景

T1 は T2 の代替ではなく前段である。未対応言語や構文誤りを含むファイルでも T1 の結果だけは必ず得られることで、「対応していない言語のファイルがグラフから消える」ことを防ぐ。

対応言語は 11 だが、目標リポジトリには文法を同梱していない言語のファイル（`Kconfig`、`Makefile`、`BUILD.gn`、アセンブリ、シェル）が多数ある。T1 が無いと、これらがパスだけの存在になる。

## やること

- 全テキスト ファイルに対して行指向の走査を行い、次を抽出する
  - **取り込み**: `#include "x.h"` / `#include <x.h>`、`import`、`use`、`require`。対象は文字列のまま記録し、解決は行わない（解決は M3）
  - **定義候補**: 言語ごとの軽量な字句規則で、定義らしき行を拾う。確度は `EXTRACTED` とし、位置と原文を根拠として保持する
  - **根拠コメント**: `TODO:` / `FIXME:` / `NOTE:` / `HACK:` / `SAFETY:` / `XXX:` を `Note` ノードにし、直後のシンボルへの `EXPLAINS` 候補として記録する
- 同じファイルを T2 が扱えた場合は T2 の結果を優先し、T1 の定義候補で重複を作らない。取り込みと根拠コメントは T1 の結果を使う
- 走査は `Span` ベースで行い、行ごとの文字列割り当てをしない
- 極端に長い 1 行、極端に多い行数でも線形時間で終わる。行長と行数の上限を設け、超過は診断して打ち切る
- 非 UTF-8 のファイルでも壊れない。復号の扱いは 022 に従う

## 設計上の注意

- T1 は tree-sitter に依存しない。解析器が無い環境でも同じ結果を出す（[設計判断](../../docs/decisions.md) ADR-3 の代償 3）
- 文字列リテラルやコメント内の `#include` らしき行を拾わないための最低限の状態は持つ。ただし完全なプリプロセスは行わない
- CJK 識別子を含む行でも語の境界を壊さない。バイト単位ではなく Unicode スカラー値で扱う

## 完了条件

- 解析器が無い環境でも、C / C++ / `Makefile` / `Kconfig` を含むコーパスで取り込みと根拠コメントが抽出される
- T2 が成功したファイルで、定義が二重に出ない
- 病的入力（1 行 10 MB、100 万行、NUL 混在）で打ち切りと診断が働き、クラッシュしない
- ゴールデン テスト（025）に T1 のみの期待値が含まれる
