# [P0] T2 C / C++ 構文抽出を実装する

- 種別: 実装 / M2
- 対象: `src/Srcnet.Extraction/`（新規）, `src/Srcnet.Extraction/SyntaxTree.fs:132-147`, `src/Srcnet.Core/Ids.fs:142-191`
- 依存: 014, 016
- 参照: [抽出](../docs/extraction.md) 4.2, [グラフ モデル](../docs/graph-model.md) 1, 4.2, 5

## 背景

C / C++ は目標リポジトリ（Linux カーネル、Chromium）の本体であり、M2 の中心である。tree-sitter の `c` / `cpp` 文法は同梱済みで、`Parsing.parse` が構文木を返すところまでできている。残るのは「木からグラフを作る」規則の実装である。

## やること

- `c` / `cpp` の構文木から次のノードを生成する
  - `Type`: `struct` / `union` / `enum` / `class` / `typedef` の対象
  - `Function`: 関数、メソッド、コンストラクター、デストラクター
  - `Field`: メンバー変数
  - `Variable`: 大域変数、静的変数
  - `Constant`: `enum` の要素、定数マクロ
  - `Macro`: 関数形式マクロ（018 で扱う）
- 宣言と定義を区別する
  - ヘッダーの宣言は `DECLARES` エッジと `DeclarationOnly` フラグ
  - 実装の定義は `DEFINES` エッジと `Definition` フラグ
- `CONTAINS` エッジを張る。ファイル → シンボル、型 → メンバー
- 修飾名を構成する
  - C++: 名前空間・クラス・構造体の入れ子を `::` で連結する
  - C: 翻訳単位が単位。`static` は内部リンケージであることをフラグで区別し、修飾名にファイルの区別を含める
  - CJK 識別子を含む名前は NFC 正規化して記録する
- 序数（`ordinal`）を割り当てる。同一スコープで名前と種別が衝突する場合に、出現位置順で決定的に振る（[グラフ モデル](../docs/graph-model.md) 4.2）。ID にはバイト位置と行番号を含めない
- `docRef` は直前のドキュメント コメントの**原文範囲**を指す。要約は生成しない
- 呼び出し・参照・継承・型の使用は、016 の参照候補として記録する
- 構文誤りを含む木でも部分結果を返す。`Node.HasError` の部分木は診断として数え、抽出を止めない

## 設計上の注意

- 走査は `SyntaxTree.descendants` の明示的スタックを使う。再帰にすると深い入れ子で stack を使い切る
- ノードの本文取得は `Node.Slice` / `Node.Text` を使い、範囲検査を重ねて行わない
- 木は必ず `use` で破棄する。ノードは所属する木より長く生存できない

## 完了条件

- 小さな固定コーパスに対する golden が macOS と Windows で一致する（025）
- CJK 識別子を含む C / C++ ファイルで、名前と修飾名が正しく抽出される（T-4）
- 構文誤りを含むファイルで、誤り箇所以外のシンボルが抽出される
- 同一ファイルを二度抽出した結果が完全に一致し、ノード ID が安定する
