# [P1] ignore ファイル読取を有界かつキャンセル可能にする

- 種別: 可用性 / リソース制御
- 対象: `src/Srcnet.Discovery/Walk.fs:139-147`, `src/Srcnet.Discovery/Ignore.fs:261-285`
- 信頼度: 100%

## 問題

ignore ファイルだけが通常コンテンツ用の保護された読取経路を通らず、同期 `File.ReadLines` で処理される。

- FIFO やデバイスを開くと無期限にブロックし得る
- `CancellationToken` が伝播されない
- バイト数と一行の長さに上限がない
- `MaxRulesPerFile` 到達後も、ファイル末尾まで列挙を続ける

## 確認結果

`.gitignore` を FIFO にした一時リポジトリで `srcnet index` を実行すると、1.5 秒を超えても完了せず、外部からプロセスを終了する必要があった。

## 影響

信頼できないリポジトリ内の特殊ファイルまたは巨大 ignore ファイルにより、索引処理を停止させたり、CPU、メモリ、I/O を過剰消費させたりできる。Ctrl-C でも速やかに停止できない。

## 対応案

- リンクでない通常ファイルだけを開く
- ignore ファイルの最大バイト数と最大行長を定義する
- 読取中に定期的にキャンセルを確認する
- 規則数上限へ達した時点で列挙を停止する
- 上限超過と読取失敗を明示的な結果として呼び出し側へ返す

## 完了条件

- FIFO、特殊ファイル、巨大一行、巨大ファイル、規則数超過の回帰テストがある
- キャンセル後、定めた時間内に `OperationCanceledException` で停止する
- ignore ファイルに対する処理量が設定済み上限内に収まる
