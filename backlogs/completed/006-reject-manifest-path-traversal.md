# [P2] マニフェストのセグメント名によるパストラバーサルを拒否する

- 種別: セキュリティー / 成果物検証
- 対象: `src/Srcnet.Storage/Manifest.fs:207-221`, `src/Srcnet.Storage/Verify.fs:80-85,261-285`, `src/Srcnet.Storage/Stats.fs:85-100`
- 信頼度: 100%

## 問題

マニフェストの `segments[].name` を検証せず、`Path.Combine(outputDirectory, name)` で物理パスへ変換している。絶対パス、`../`、Windows の `..\`、ドライブ名、UNC パスなどを拒否していない。

## 確認結果

正常な `.files` セグメントを成果物ディレクトリの一つ上へコピーし、マニフェスト内の名前を `../outside.files` に変更した。

- `srcnet verify` は成果物外のファイルを読み、終了コード `0` で「問題ありません」と報告した
- `srcnet stats` も成果物外のファイルを memory map し、終了コード `0` で集計した

## 影響

改変された成果物を開くだけで、成果物ディレクトリ外の任意ファイルを読み取り、ハッシュ計算または memory map の対象にする。信頼境界を破り、情報漏えいの補助、クラッシュ、過剰 I/O につながる。

## 対応案

- セグメント名を正規化済み相対パスとして検証する
- rooted path、親参照、空要素、不正区切り、代替データストリームを拒否する
- 許可する名前を `segments/<generation>/<known-name>` のように狭く定義する
- 結合後の実体パスが成果物ルート配下にあることを、OS に応じた比較規則で再確認する

## 完了条件

- `/absolute`、`C:\absolute`、UNC、`../`、`..\`、混在区切りのテストがある
- `verify`、`stats`、将来の reader が同一の検証済みパス変換を使用する
- 拒否時に成果物外のファイルを開かず、形式エラーとして終了する
