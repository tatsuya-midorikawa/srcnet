# [P0] C / C++ のゴールデン テストと固定コーパスを用意する

- 種別: テスト / M2
- 対象: `tests/Srcnet.Tests/`, `.github/workflows/`
- 依存: 015, 017, 018, 019
- 参照: [ロードマップ](../../docs/roadmap.md) M2 完了条件, [テスト](../../docs/testing.md) 2, 5, T-1, T-4

## 背景

M2 の完了条件は「`linux` コーパスでシンボル抽出が完了し、ゴールデン テストが通る」である。ゴールデン テストは抽出規則の回帰を検出する唯一の手段であり、規則の変更が意図した差分だけを生むことを保証する。

## やること

- 小さな固定コーパスを本リポジトリ内に持つ（外部依存にしない）
  - `micro`: 宣言と定義、名前空間、テンプレート、継承、マクロ、`#ifdef` を最小限ずつ含む C / C++
  - `cjk`: CJK 識別子・コメント・ファイル名を含むファイル。符号化は UTF-8 と、022 で対応を決めたレガシー符号化
  - `pathological`: 024 の病的入力（共用でよい）
- 期待値を決定的なテキスト表現で保存する
  - ノード（種別、名前、修飾名、行範囲、フラグ）とエッジ（種別、始点、終点、確度）を安定した並びで出力する
  - 差分が人間に読める形式にする。バイナリ成果物を期待値にしない
- 構文解析器が無い環境では T1 の期待値だけを検証する。テストが「解析器が無いから通った」状態を、スキップとして明示する
- CI に反映する
  - `parser` ジョブ（macOS / Windows）で、文法を構築したうえで golden と決定性を回す
  - `build-test` ジョブでは、解析器なしの T1 golden を回す
- 期待値の更新手順を文書化する。手作業での書き換えではなく、生成コマンドで更新できるようにする

## 設計上の注意

- 期待値のファイルは LF・BOM なし UTF-8 で保存する（ADR-7）。改行の差が全件の差分になる状況を作らない
- 期待値にバイト位置を含めると、コーパスの些細な編集で全件が変わる。行範囲を主とし、バイト位置は必要な項目に限る

## 完了条件

- macOS と Windows で golden が一致する
- 解析器が無い環境でもテスト一式が通る（該当項目はスキップとして明示される）
- 期待値の更新手順が文書化され、実行できる
- 抽出規則を変えたときに、意図した差分だけが golden に現れる
