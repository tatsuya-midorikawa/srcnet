# [P1] マニフェストだけを切替点にした世代単位の公開へ変更する

- 種別: 整合性 / 並行実行
- 対象: `src/Srcnet.Storage/Manifest.fs:171-200`
- 信頼度: 100%

## 問題

`Manifest.publish` は旧 `segments` を退避し、新 `segments` を同じパスへ移動してから、最後に `manifest.json` を置き換える。セグメント名も世代間で `segments/0001.*` のまま再利用される。

このため公開中には、次の不整合な状態が外部から観測できる。

1. 旧マニフェストが参照するセグメントが一時的に存在しない
2. 旧マニフェストが新世代の同名セグメントを参照する
3. マニフェスト読取後、セグメントを開く前に世代が切り替わる

`stats` などはマニフェストとセグメントを別々に開くため、旧マニフェストの件数と新セグメントの集計結果を混在させても成功し得る。

## 影響

- 並行する `stats`、`verify`、将来の query が欠損エラーになる
- 異なる世代の値を混ぜた、整合しない結果を正常終了で返す
- 公開途中のプロセス停止で、既存成果物を読めない状態にする

## 対応案

- セグメントを世代固有の不変パスへ書き出す
- 新マニフェストが新世代のパスだけを参照するようにする
- `manifest.json` の原子的置換を唯一の公開切替点にする
- 旧世代は公開切替後に削除し、開いている読取側との Windows 互換性も考慮する

## 完了条件

- 再索引と `stats` / `verify` を並行反復しても、欠損または世代混在が発生しない
- 公開手順の各段階で強制終了しても、再起動後に旧世代か新世代のどちらか一方を完全に読める
- マニフェストに記録された件数、長さ、チェックサムと、読まれたセグメントの世代が必ず一致する
