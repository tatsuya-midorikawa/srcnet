# [P2] テスト・生成・ベンダー コードの判定を抽出結果へ反映する

- 種別: 実装 / M2
- 対象: `src/Srcnet.Discovery/Classify.fs:103-147`, `src/Srcnet.Extraction/`（新規）
- 依存: 017
- 参照: [抽出](../docs/extraction.md) 7, 8, [クエリと CLI](../docs/query-and-cli.md) 3

## 背景

検索順位はフラグによる減点を含む（[クエリと CLI](../docs/query-and-cli.md) 3 の 4 段目）。減点の対象はシンボルであり、現在フラグを持っているのはファイルだけである。

`Classify.pathFlags` はパスとファイル名から `Vendored` / `Test` / `Generated` を付けるが、内容を読まないため、生成物マーカー コメントとテスト マクロは検出できない。

## やること

- ファイルのフラグをシンボルへ伝播する。`Vendored` と `Generated` は所属ファイルから引き継ぐ
- テスト検出を内容の規則で補う
  - C / C++: `TEST(`、`TEST_F(`、`TEST_P(`、`TYPED_TEST(` を含む定義に `Test` フラグ
  - パスとファイル名の規則は既存の `pathFlags` を使う
  - 命名規約から対象シンボルを推定した場合は `AMBIGUOUS` とする。`TESTS` エッジの生成は解決が要るため M3 で行い、M2 は参照候補として記録する（016）
- 生成コードのマーカー コメント（`DO NOT EDIT`、`autogenerated`、`@generated` など）をファイル先頭の一定範囲から検出し、`Generated` フラグを付ける。走査範囲に上限を設ける
- ベンダー コードは除外しない。フラグ付きで保持する（[抽出](../docs/extraction.md) 8）

## 設計上の注意

- マーカーの検出範囲をファイル全体にすると、`DO NOT EDIT` を本文に含むだけのファイルまで生成扱いになる。先頭の数十行に限る
- 検出規則は決定的で、大文字小文字の畳み込みは `Unicode.caseFold` を使う。ロケール依存の比較をしない

## 完了条件

- `third_party/` 配下のシンボルに `Vendored` が付く
- `TEST_F` で定義された関数に `Test` が付く
- 先頭に `DO NOT EDIT` を持つファイルのシンボルに `Generated` が付き、本文中にのみ含むファイルには付かない
- フラグがゴールデン テストの期待値に含まれる（025）
