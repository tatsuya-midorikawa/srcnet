# [P2] Linux を対応実行環境に含めるかを決める

- 種別: 決定 / M2
- 対象: `docs/decisions.md`, `docs/roadmap.md`, `docs/platform-and-i18n.md`, `docs/testing.md`, `.github/workflows/`
- 依存: 026
- 参照: [ロードマップ](../../docs/roadmap.md) 未決事項, [設計判断](../../docs/decisions.md) 未決事項, [テスト](../../docs/testing.md) 4

## 背景

解析**対象**としての Linux カーネルは主目標だが、**実行環境**としての Linux を対応プラットフォームに含めるかは未決である。決着させる時期は M2 とされている。

[テスト](../../docs/testing.md) 4 は現在「Linux ランナーはコーパス取得の効率のために使ってよいが、合否判定には使わない」としており、この状態のまま M3 以降へ進むと、CI の位置づけが曖昧なまま増える。

## やること

- 次を比較して決定し、[設計判断](../../docs/decisions.md) に ADR として記録する
  - 大規模コーパスの取得と実行の効率（Linux ランナーが最も安価で速い）
  - 対応コストの増加（3 OS 分の決定性検証、パス正規化、ファイル システムの差異、大文字小文字の扱い）
  - 決定性要件への影響。対応環境を増やすと T-1 の 3 が 3 通りの突き合わせになる
  - ネイティブ構築（tree-sitter）の追加負担
- 含める場合
  - [テスト](../../docs/testing.md) 4 の CI マトリクスへ Linux を追加し、合否判定の対象にする
  - [移植性と国際化](../../docs/platform-and-i18n.md) に Linux 固有の扱い（大文字小文字を区別するファイル システム、パス長、リンク）を追記する
- 含めない場合
  - Linux ランナーの用途をコーパス取得と補助的な検証に限る旨を明文化し、合否判定に使わない理由を残す

## 完了条件

- ADR が [設計判断](../../docs/decisions.md) に追加され、却下した選択肢と根拠が記録されている
- [ロードマップ](../../docs/roadmap.md) の未決事項から本項目が外れる
- 決定に応じて CI と関連文書が更新されている
