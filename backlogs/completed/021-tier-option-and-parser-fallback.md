# [P1] `--tier` オプションと解析器不在時の縮退を実装する

- 種別: 実装 / M2
- 対象: `src/Srcnet.Cli/Args.fs:15-24`, `src/Srcnet.Cli/Commands.fs:109-129,255-312`, `src/Srcnet.Extraction/Parsing.fs:45-70`
- 依存: 015, 017, 020
- 参照: [クエリと CLI](../../docs/query-and-cli.md) 2.1, 2.2, [設計判断](../../docs/decisions.md) ADR-3

## 背景

[クエリと CLI](../../docs/query-and-cli.md) 2.1 は `srcnet index` に `--tier <0|1|2|3>` を定めているが、`Args.IndexArguments` に対応する項目がない。

また ADR-3 の代償 3 のとおり、構文解析器が無い環境では構造グラフ（M1）相当へ縮退して走査自体は成立させる必要がある。この縮退が利用者から見て明示されないと、「成果物が小さいのは対象が小さいからか、解析器が無いからか」を区別できない。

## やること

- `--tier` を実装する。既定は 2
  - `0`: 走査のみ（M1 相当）
  - `1`: T1 まで
  - `2`: T2 まで
  - `3`: 未対応。利用者エラー（終了コード 2）として、`--tier 3` はビルド構成に基づく解決（T3）であり未実装であることを伝える
- 構文解析器または対象言語の文法が無い場合は T1 へ縮退する
  - 縮退の診断はファイルごとではなく実行あたり 1 回にまとめる。数千万ファイルで同じ診断を繰り返さない
  - 縮退しても終了コードは失敗にしない。診断があるため 4 を返す
- `index` の出力に、実際に適用した段階と、段階ごとに処理したファイル数、抽出できなかったファイル数を含める。テキスト出力と JSON 出力の両方に反映する
- 適用した段階は成果物へ記録する（020）

## 設計上の注意

- `Parsing.isAvailable` は共有ライブラリの有無を一度だけ確かめる。ファイルごとに判定を繰り返さない
- `--tier 0` の成果物は M1 の成果物と論理的に等価でなければならない。段階を下げるだけで別の形式にならないようにする

## 完了条件

- 構文解析器が無い環境で `index` が成功し、T1 までの結果が得られる
- `--tier 0` / `1` / `2` の成果物が、段階に応じて期待どおり変わる
- `--tier 3` と `--tier 9` がいずれも利用者エラーとして拒否され、内部エラーにならない
- 縮退時の診断が実行あたり 1 回で、`stderr` に出る（`stdout` を汚さない）
