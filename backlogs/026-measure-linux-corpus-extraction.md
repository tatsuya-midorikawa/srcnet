# [P1] `linux` コーパスでシンボル抽出を実測する

- 種別: 検証 / M2（M1 未了の実測を兼ねる）
- 対象: `docs/performance.md`, `docs/roadmap.md`, `.github/workflows/`
- 依存: 019, 021, 025
- 参照: [ロードマップ](../docs/roadmap.md) M1 未了, M2 完了条件, [テスト](../docs/testing.md) T-7, [性能](../docs/performance.md)

## 背景

M2 の完了条件は `linux` コーパスでのシンボル抽出の完了であり、M1 の未了項目である「`linux` コーパスでの実測」も同じ実行で解消できる。

現在の [性能](../docs/performance.md) の目標値は実測に基づいていない。M2 の時点で得られる実測値を入れておかないと、M7 で目標を見直す際の基準がない。

## やること

- コーパスをコミット SHA で固定して取得する（[テスト](../docs/testing.md) 5）。CI ではキャッシュし、毎回の取得を避ける
- `srcnet index --tier 2` を macOS と Windows で実行し、次を記録する
  - 所要時間（並列度ごと）、ピーク RSS、生成物サイズ
  - ノード種別ごとの件数、エッジ種別ごとの件数、参照候補の件数
  - 診断の内訳
- 抽出できなかったファイルの内訳を、言語別・理由別（文法なし、時間切れ、サイズ上限、符号化）に出す
- 両 OS の成果物がバイト単位で一致することを確認する（T-1 の 3）
- 実測値を [性能](../docs/performance.md) へ反映し、目標値との差を明示する。目標に届かない場合は原因を記録し、M7 で扱う項目として残す

## 設計上の注意

- ホスト型ランナーの制限に収まらない可能性がある。収まらない場合は、[ロードマップ](../docs/roadmap.md) の未決事項「大規模コーパスを CI で回すための実行基盤」として記録し、定期実行の `corpus-large` ジョブの構成を決める
- 走査項目数の上限（既定 8,000,000）に達しないことを確認する。達する場合は上限の妥当性を併せて見直す

## 完了条件

- `linux` コーパスの走査と抽出が完了し、成果物が公開される
- macOS と Windows の成果物がバイト単位で一致する
- 実測値が [性能](../docs/performance.md) に記録される
- 抽出できなかったファイルの内訳が説明でき、M3 以降で扱う項目として整理されている
