# [P1] `linux` コーパスでシンボル抽出を実測する

- 種別: 検証 / M2（M1 未了の実測を兼ねる）
- 対象: `docs/performance.md`, `docs/roadmap.md`, `.github/workflows/`
- 依存: 019, 021, 025
- 参照: [ロードマップ](../docs/roadmap.md) M1 未了, M2 完了条件, [テスト](../docs/testing.md) T-7, [性能](../docs/performance.md)

## 背景

M2 の完了条件は `linux` コーパスでのシンボル抽出の完了であり、M1 の未了項目である「`linux` コーパスでの実測」も同じ実行で解消できる。

[性能](../docs/performance.md) に macOS の測定記録はあるが、固定 SHA の誤記が判明した。
正しい入力での再現と Windows 側の実行が済むまで、受け入れ完了の根拠にはできない。

## やること

- コーパスをコミット SHA で固定して取得する（[テスト](../docs/testing.md) 5）。CI ではキャッシュし、毎回の取得を避ける
- `srcnet index --tier 2` を macOS と Windows で実行し、次を記録する
  - 所要時間（並列度ごと）、ピーク RSS、生成物サイズ
  - ノード種別ごとの件数、エッジ種別ごとの件数、参照候補の件数
  - 診断の内訳
- 抽出できなかったファイルの内訳を、言語別・理由別（文法なし、時間切れ、サイズ上限、符号化）に出す
- 両 OS の成果物がバイト単位で一致することを確認する（T-1 の 3）
- 実測値を [性能](../docs/performance.md) へ反映し、目標値との差を明示する。目標に届かない場合は原因を記録し、M7 で扱う項目として残す

## 設計上の注意

- ホスト型ランナーの制限に収まらない可能性がある。収まらない場合は、[ロードマップ](../docs/roadmap.md) の未決事項「大規模コーパスを CI で回すための実行基盤」として記録し、定期実行の `corpus-large` ジョブの構成を決める
- 走査項目数の上限（既定 8,000,000）に達しないことを確認する。達する場合は上限の妥当性を併せて見直す

## 進捗（2026-09）

macOS 側の参考記録は [性能](../docs/performance.md) 5.1 に残す。以下は当時の記録であり、
入力同一性は要再確認である。

- `linux` v6.6（81,681 ファイル / 1.29 GiB）の走査と抽出が完了し、`verify` が通った
- 所要時間は T2・既定の並列度で 72.4 秒。目標の 5 分に対して達成
- ピーク RSS は 7.95 GiB で、目標の 4 GiB に対して**未達**。段 4 の spill が未実装であり、
  M7 の `--memory-limit` と併せて解く項目として [ロードマップ](../docs/roadmap.md) へ記録した
- `--jobs 1` と `--jobs 10` の成果物はバイト単位で一致した（T-1 の 1）
- 抽出できなかった 15 件の内訳（上限超え 10、バイナリ 3、符号化不明 2）を記録した
- 走査項目数の上限（8,000,000）には達していない（81,681 件）

**レビューで修正した点:** CI の存在しない SHA を v6.6 の実コミット
`ffc253263a1375a65fa6c9f62a893e9767fbebfa` へ修正した。キャッシュを OS 別に分け、
改行変換を止め、HEAD と checkout の差分を検査する。診断付きの終了コード 4 は
`complete: true` と併せて扱い、PowerShell でも実行失敗を隠さない。

**残り:** 正しい SHA での macOS 再測定、Windows の実測、両 OS の成果物一致（T-1 の 3）。
大文字小文字を区別するボリューム、長いパス、実体としての symlink を両 OS で揃える。
Windows のピーク RSS 計測も必要で、現行 CI の経過時間だけでは代用できない。
`corpus-large` / `corpus-large-determinism` は設定済みだが、成功した実行と計測記録が揃って初めて完了にする。
