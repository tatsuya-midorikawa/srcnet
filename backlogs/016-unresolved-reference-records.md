# [P0] 未解決参照の記録形式を定める

- 種別: 実装 / M2
- 対象: `src/Srcnet.Storage/Format.fs:29-46,179-219`, `src/Srcnet.Storage/Writer.fs:162-490`, `src/Srcnet.Extraction/`（新規）
- 依存: 014
- 参照: [抽出](../docs/extraction.md) 5, [ストレージ](../docs/storage.md) 3, [グラフ モデル](../docs/graph-model.md) 3

## 背景

T1 と T2 が見つける `#include`、呼び出し、参照、継承は、抽出した時点では相手のノード ID が決まらない。解決は M3 の仕事である。

M2 が「抽出した事実」をどこにも残さないと、M3 は同じファイルをもう一度解析することになる。抽出と解決の間を繋ぐ記録形式を、セグメント形式の一部として先に決める必要がある。

## やること

- 参照候補レコードを定義する
  - 発生元ノードの密インデックス
  - エッジ種別（`INCLUDES` / `CALLS` / `REFERENCES` / `INHERITS` / `IMPLEMENTS` / `TYPED_AS` / `EXPLAINS`）
  - 対象の生テキストへの文字列参照（修飾名、短い名前、取り込みの綴りのいずれか）
  - 修飾ヒント（囲みスコープ、名前空間、取り込み閉包を引くための材料）
  - 言語、バイト範囲、行番号
  - 根拠段階の初期値（[抽出](../docs/extraction.md) 5.2 の段階番号。未解決は 0）
- `Format.SegmentKind` に参照候補の種別を追加し、`<id>.refs` として書き出す。固定長レコード + 文字列 blob 参照とし、64 バイト境界の整列と件数の不変条件検査（`Format.checkInvariants` 相当）を既存と同じ方式で持つ
- 並びは決定的にする。ソート キーは「発生元の密インデックス → エッジ種別コード → バイト位置」とする
- 解決前の確度は `EXTRACTED` とする。`RESOLVED` / `AMBIGUOUS` へ変わるのは M3

## 設計上の注意

- M3 は大域シンボル表を外部マージ ソートで構築する。参照候補も同じ方式で流せるよう、レコードは固定長を保ち、可変長は blob 参照にする
- 未解決のまま `INCLUDES` エッジを CSR へ書かない。CSR の隣接先は密インデックスであり、解決前の候補を入れる場所がない

## 完了条件

- 参照候補の書き出しと読み取りが往復で一致する（property テスト）
- 件数・オフセット・文字列参照が不正なセグメントが、内部エラーではなくドメイン エラーとして拒否される
- 同一入力から二度生成した `.refs` がバイト単位で一致する（T-1）
- M2 で抽出した参照候補の総数が `stats` から確認できる
