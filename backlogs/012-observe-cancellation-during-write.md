# [P2] 大規模セグメント書出し中と公開直前にキャンセルを確認する

- 種別: キャンセル / 長時間処理
- 対象: `src/Srcnet.Storage/Writer.fs:242-437`, `src/Srcnet.Cli/Commands.fs:181-203`
- 信頼度: 98%

## 問題

`Writer.write` は書出し開始前に一度だけ `CancellationToken` を確認し、その後の文字列、ファイル、ノード、CSR、ID map の全ループでは確認しない。`buildIndex` も書出し完了後、キャンセルを再確認せずに `Manifest.publish` を実行する。

## 影響

- 大規模リポジトリでは Ctrl-C 後も長時間 CPU と I/O を使い続ける
- 利用者が中断したつもりでも、新成果物を公開して正常終了し得る
- CLI が掲げる中断終了コード `5` と、公開しないという期待を満たさない

## 対応案

- 各大規模ループで、適切な間隔ごとにキャンセルを確認する
- セグメント境界と `Manifest.publish` の直前に必ず確認する
- `OperationCanceledException` をそのまま上位へ伝え、staging を破棄する
- キャンセル確認の頻度は throughput を損なわないよう benchmark で決める

## 完了条件

- 各セグメントの書出し途中でキャンセルする回帰テストがある
- キャンセル後は定めた時間内に終了コード `5` で停止する
- 既存の公開済みマニフェストとセグメントを変更しない
- staging が後続実行を妨げず、確実に回収される
